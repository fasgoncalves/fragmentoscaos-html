SoftBancada: uma bancada de ferramentas para programadores, toda no telemóvel

Publicado em 2026-11-27 19:58:55

Android · Ferramentas

Cliente HTTP e WebSocket, Git, SQLite, JWT, cron, SemVer, estruturas de dados e dados de teste numa só app Android, sem contas, sem nuvem e sem telemetria.

Há dias em que um programador abre seis separadores, duas apps e um terminal só para ver se um JWT expirou, se uma expressão cron dispara às 3 da manhã de domingo, ou que commit mudou aquele ficheiro. A SoftBancada junta essas pequenas ferramentas numa só app Android, que corre no telemóvel e no tablet, sem contas, sem nuvem e sem telemetria.

Este é o relato técnico de como foi feita: as doze ferramentas, as decisões menos óbvias (porque escrevi um cliente HTTP e um leitor de Git de raiz) e os limites que convém conhecer antes de confiar nela.

O problema

As ferramentas de bolso para programadores costumam ter um de dois defeitos. Ou são sites que pedem para colar lá um token, um esquema de base de dados ou uma resposta de API com dados de clientes, ou são apps que querem uma conta, sincronizam tudo e enviam estatísticas de uso para algum lado. Para quem trabalha com dados reais, nenhuma das duas serve.

A regra de partida da SoftBancada foi: tudo é calculado no aparelho, e a rede só é usada quando o utilizador a pede, por exemplo para enviar um pedido HTTP ou abrir um repositório por SFTP. Não há IA, não há serviços externos, e os resultados são determinísticos: os mesmos dados de entrada dão sempre o mesmo resultado.

Doze ferramentas, quatro grupos

API

  • Cliente HTTP / REST. GET, POST, PUT, PATCH, DELETE, HEAD e OPTIONS, com cabeçalhos, corpo JSON/XML/texto/formulário validado antes de enviar, resposta formatada e tempos por fase: DNS, ligação, TLS e primeiro byte. Ambientes com {{variáveis}}, coleções exportáveis em JSON e histórico.
  • Cliente WebSocket. ws:// e wss://, mensagens de texto e binárias, ping e registo de tudo o que passa.
  • JSON · SQL · cron. Erros com linha e coluna, formatar e minificar; SQL verificado pelo próprio SQLite; cron com descrição em linguagem corrente e próximas execuções no fuso escolhido; modelos JSON/SQL com variáveis e filtros.
  • JWT · Base64 · URL · tempo. Descodificação local de JWT e verificação de assinaturas HS256/384/512, codificações, hashes e conversão de timestamps Unix/ISO-8601 entre fusos.

Git

  • Explorador Git, só de leitura, sobre uma pasta do aparelho ou um servidor SFTP: histórico, ramos, etiquetas, diffs por ficheiro, estado da árvore de trabalho e navegação nos ficheiros.
  • .gitignore · .editorconfig · licenças para Kotlin/Android, Python, C/C++, Rust, Shell e SQLite, com verificação de consistência entre vários repositórios.
  • SemVer · changelog. Próxima versão, intervalos ao estilo npm e Maven, e CHANGELOG.md no formato «Keep a Changelog» a partir de mensagens Conventional Commits ou de entradas manuais.

Estruturas

  • Estruturas de dados e grafos passo a passo: árvores BST e AVL, heaps, tabelas de hash, filas, pilhas, BFS, DFS, Dijkstra e ordenação topológica.
  • Máquinas de estados escritas com setas, JSON ou YAML, simuladas com guardas e variáveis, com deteção de estados inalcançáveis, becos sem saída e transições ambíguas; exportação para Mermaid, DOT ou Kotlin, e conversão de NFA em DFA.
  • Cores · unidades · 2D. HEX/RGB/HSL, contraste WCAG, px/dp/sp por densidade de ecrã e matrizes de transformação.

Dados

  • Explorador SQLite: esquema, índices, triggers, consultas só de leitura e exportação para CSV, JSON ou Markdown.
  • Analisador estático: TODO/FIXME/NOTE, linhas, funções, complexidade, blocos duplicados e cabeçalhos de licença, com relatório em Markdown.
  • Dados sintéticos com semente fixa, casos limite e NIF português válido, em CSV, JSON, JSONL ou SQL.

Por dentro: decisões que não são as óbvias

Um cliente HTTP escrito sobre sockets

O HttpURLConnection do Android não aceita PATCH sem truques e não diz quanto tempo demorou cada fase do pedido. Por isso a SoftBancada tem um cliente HTTP/1.1 próprio, sobre sockets: resolve o nome, liga, faz o aperto de mão TLS e lê a resposta, medindo cada passo. Trata chunked, gzip, redirecionamentos e respostas grandes (que são cortadas a partir de um limite, com aviso).

Para servidores caseiros com certificados próprios há fixação de certificados: quando o sistema não confia no certificado, a app mostra a impressão digital SHA-256 e o utilizador decide se a aceita para aquele anfitrião. Não há nenhum botão «ignorar todos os erros de TLS». O tráfego http:// em claro é permitido, porque muitas APIs de desenvolvimento correm em localhost ou na rede local.

Um leitor de Git próprio, em vez de JGit

O JGit espera um sistema de ficheiros normal. Numa app Android moderna, as pastas do utilizador chegam pelo Storage Access Framework (SAF), e um repositório num servidor chega por SFTP. Em vez de copiar repositórios inteiros, escrevi um leitor só de leitura sobre uma interface mínima (stat, list, read com posição e tamanho), que funciona da mesma forma nas duas origens.

Lê objetos soltos e packfiles (índices v1 e v2, deltas OFS_DELTA e REF_DELTA), referências e packed-refs, o índice nas versões 2, 3 e 4, e repositórios SHA-1 ou SHA-256. Os diffs de linhas usam o algoritmo de Myers, com blocos ao estilo git diff. Uma cache LRU de objetos evita ler o mesmo pacote vezes sem conta por SFTP.

Deixar o SQLite validar o SQL

Escrever um analisador de SQL completo seria trabalho para meses e daria sempre respostas ligeiramente diferentes das do motor real. A solução é mais simples: a app prepara a instrução numa base SQLite vazia, em memória, opcionalmente depois de criar o esquema do utilizador. Se o SQLite aceita, a sintaxe está certa; se não, a mensagem de erro é a dele. No explorador de bases, uma guarda lexical garante que só passam instruções de leitura, e o ficheiro é aberto a partir de uma cópia, para nunca tocar no original.

Dados de teste que se repetem

Os dados sintéticos usam um gerador SplitMix64 com uma semente por campo, derivada da semente global e do nome do campo. Assim, acrescentar uma coluna nova não muda os valores das outras, e a mesma semente gera exatamente as mesmas linhas hoje, amanhã e noutro aparelho. É o tipo de pormenor que torna um teste reproduzível.

Motores em Kotlin puro

Toda a lógica (Git, HTTP, WebSocket, cron, SemVer, máquinas de estados, estruturas, dados sintéticos, cifra) vive em Kotlin puro, sem depender do Android, e é testada numa JVM com 47 testes. Os testes do Git comparam o leitor com o git real, e os da rede correm contra servidores HTTP, TLS, WebSocket e SFTP embebidos no próprio teste.

Privacidade e segurança

O quêComo
RedeSó a permissão INTERNET, usada apenas quando o utilizador envia um pedido ou abre um servidor. Sem contas, sem nuvem, sem telemetria.
Dados guardadosFicheiro JSON cifrado com AES-256-GCM, chave por ficheiro derivada com HKDF a partir de um segredo protegido pelo Android Keystore.
TLSSó certificados do sistema ou fixados pelo utilizador, por SHA-256 e por anfitrião.
SFTPChave do servidor fixada na primeira ligação; se mudar, a app recusa e avisa.
BloqueioNo telemóvel, biometria ou credencial do aparelho ao abrir e após 30 s em segundo plano. No tablet, sem bloqueio próprio. Capturas de ecrã bloqueadas em ambos.
Cópia entre aparelhosFicheiro .slb cifrado com palavra-passe (AES-256-GCM, PBKDF2 com 200 000 iterações). As palavras-passe SFTP nunca são exportadas.

Os dados ficam num ficheiro JSON cifrado em vez de numa base SQLite/Room. É um desvio consciente, comum a todas as apps SofteLabs: para o volume de dados de uma app destas, um ficheiro cifrado por inteiro é mais simples e não deixa nada em claro.

A pilha técnica

  • Kotlin 2.0.21, Jetpack Compose com Material 3 (BOM 2025.04.01)
  • Android 10 (API 29) ou superior, compilado para a API 36; telemóvel e tablet na mesma app, com barra inferior ou barra lateral conforme o ecrã
  • JSch 0.2.20 para SFTP; tudo o resto sem bibliotecas de terceiros
  • Interface bilingue, português e inglês, segundo o idioma do sistema
  • Documentação de utilizador e técnica dentro da app, nas duas línguas

Limites, ditos às claras

A SoftBancada é uma bancada de consulta e verificação, não um IDE nem um cliente Git completo.

  • O Git é só de leitura: não faz commits, push nem pull. Não lê o formato reftable nem aplica autocrlf ou filtros.
  • O cliente HTTP fala apenas HTTP/1.1.
  • O explorador SQLite lê uma cópia sem o ficheiro -wal, por isso alterações ainda não consolidadas não aparecem.
  • O analisador estático é lexical: contagens de funções e complexidade são aproximações.
  • As licenças longas (Apache, GPL, LGPL, MPL) aparecem como aviso com o endereço oficial, não com o texto completo.
  • Pastas e repositórios vêm do aparelho ou de SFTP; SMB não é suportado.

Para terminar

A SoftBancada nasceu de uma irritação pequena e repetida: ter de confiar dados de trabalho a sites e serviços só para fazer contas que um telemóvel faz sozinho. O resultado é uma app que não precisa de saber quem é o utilizador, não tem para onde enviar nada e dá sempre a mesma resposta à mesma pergunta.

Se experimentar e alguma ferramenta falhar, ou faltar uma que usa todos os dias, diga-me. É assim que a bancada cresce.
